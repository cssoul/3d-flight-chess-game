# 2026-10-14 — 3D 飞行棋「SKYLINE RALLY / 云顶都会」

## 项目定位
Vue3 + TS + Three.js + Vite 的 3D 飞行棋。硬约束：**所有几何/材质/贴图/音效全部代码生成，零 GLB/GLTF/HDR/图片/音频资源**。
已用 `find src public` 校验：只有 .ts/.vue/.css，无任何二进制资源。开发端口 5288。

## 本轮（10-14）解决的视觉问题 —— 都值得记
1. **白昼"白压白"**：原预设 hemi 1.0 / ambient 0.22 / env 0.9 全在托底，阴影侧和受光侧亮度几乎一样，整个画面像蒙雾。
   解法是**拉开层次而不是调亮**：key 2.0→2.6、hemi 1.0→0.58、ambient 0.22→0.12、env 0.9→0.45、fill 0.42→0.24。
2. **棋盘没有"落脚的边界"**：底板和白铺装同色（都 #eef2f5 系）。改 `buildPlate()`：
   底板外缘加一圈深色包边（#93a0a9，0.62 宽）、顶面提亮到 #f5f8f9、**并在格块脚下加一圈浅灰"跑道"底衬**（#d9e0e4），
   格块这才读成"铺在轨道上的筹码"。跑道圆角要随外扩量同步增大（`RING.corner + d`），否则环宽不均。
3. **格块在强光下发白**：改用 `emissiveMap: tex` + `emissive: 0xffffff`（而不是平涂 `TILE_STYLE.color`）。
   平涂会把 icon 洗掉；用自身贴图发光能整块提亮却保住 icon 与色块的内部对比。白昼 0.22 / 夜晚 0.32。
4. **context 抢色**：外圈行道树按到原点距离褪成灰调鼠尾草（`k = clamp((r-23)/26)`），
   只有广场环以内的树留饱和绿 —— 这是"彩色棋盘 / 无色 context"的 SASAKI 手法。
   注意：褪色要**降饱和**，不要**提亮度**，提亮度只会变成糖果色粉绿。
5. **地面**：`createGroundTexture("#f0ebe3", "#c2bdb3")` 暖纸灰，白广场才有色阶可压。
6. **两个真 bug**（都不是调参能救的）：
   - `board3d` 长椅：坐面 `rotY: -a` 把长轴转成了**径向**，腿却按切向摆 → 一堆斜插在草地上的木板。正解 `rotY: a + Math.PI/2`。
   - `pieces.ts` Dice：柔光盘 y 写成 `-baseY + 0.42` 且骰子 baseY=5.0，光盘被埋进广场里看不见。
     改成"世界高度" `glowWorldY = SCALE.boardTop + 0.31` 反算相对偏移；骰子抬到 6.9 才和中央雕塑（顶面约 4.15）分层。
     骰子落定的冲击环也一并从 y=2.4 改到广场面（`SCALE.boardTop + 0.36`），才读得出"砸下来"的重量。

## 第二轮：用户四条优化反馈（同日）

### ① 削城市、放大棋盘
用户原话："建筑太多了…保留 1、2 个大点的建筑 + 3、4 个小建筑即可，要更加突出飞行棋的棋盘大小。"
- `city.ts` 的 `blocks()` **整段重写**：原来是 bandA+bandB 两圈按 splits 递归切分 → 36 个 rect → `splitRect` 再切 → 90+ 栋楼。
  现在改成沿 `makeRing(39, 16)` 均匀布 **10 块地**，起点错开半个间距（`(i + 0.5) / N`）避免地标正对轴线中点。
  配比：2 地标（6 / 7 层）+ 4 小体量（3 / 4 层）+ 公园 / 水景 / 球场。
- `Rect` 加 `floors?: number`：有值即"地标体量"，铺地系数 0.84，否则 `range(0.58, 0.74)`，体型才拉得开。
- 删掉 `buildBlocks` 里按索引写死的 `specials` 表（用途已在 blocks() 排好）。
- 三角面 66k → 39k。

### ② 车辆 18 → 2
`buildCars` 的 `N = 18` 改 2；`s: peri * (i / 11)` 改 `(i / N)`（否则两车会挤在一处）；palette 换成 `["#eef2f5", "#8fb8d6"]`。
**顺带修一个真 bug**：座舱原来用 `0x2a3b48`，俯视时它是车上最显眼的一块，读成"路上的一个黑洞"。
改成带反射的蓝灰玻璃 `0x6b8496` + 收窄到 0.78×0.42×0.9。

### ③ 选中态按钮白底白字（CSS 层叠 bug）
`.btn.is-on`（白字 + 青底）与 `.btn.ghost`（半透明白底）**优先级相同**，而 `.btn.ghost` 在 style.css 里排得更靠后
→ 底色被覆盖成半透明白，但 `color:#fff` 还在生效 → HUD 上"全景 / 1× / ☀"等选中项直接看不见文字。
救法：补一条三类的 `.btn.ghost.is-on`（青底 + 白字），别靠调整声明顺序。
大厅的 `.seg button.on`（`#0e6e80` on 白底）本来就是好的，不要动。

### ④ 去掉骰子的"白色光影"
`Dice` 里那个 `glow` 光盘是 **root 的子节点**，骰子抛起时它跟着飞到半空 → 就是用户在掷骰时看到的那道移动白光。整块删掉（连带 `glowWorldY` 与 `setBaseY` 的同步逻辑）。
落定冲击也一并收：去掉额外叠的白环，青色环从 `0.7→7.6 / 0.7s` 收到 `0.4→3.0 / 0.4s`，颜色压到 `#1fa6cc`。
**原理**：加性混合的浅色大环铺在浅色广场上必然读成一片白光 —— 想要"有冲击但不脏"，环必须紧、必须饱和。

### 取景调整（为配合①②）
- `CAM.minFrustum: 40 → 37`（`baseFrustum 56 → 50`，但 1440×900 时实际由 minFrustum 夹住）。
- `CAM.defaultElevation: 38 → 35`。**关键原理**：地面在屏幕上的纵向拉伸系数是 `sin(仰角)`，
  仰角越小、近端地块越往画面里收，地标楼才不会被下边缘切掉只露个顶。
- `playIntro` 原来把 `58 - 20*k` 写死收在 38 → 改成从 `CAM.defaultElevation + 20` 起，否则改默认仰角会被开场动画悄悄覆盖。
- `App.vue` 的 `VIEWS[0]` 与 `reset()` 里的 `setView(45, 38)` 同步改成 35。
- 广场行道树间距 6.4 → 9.2（取景收紧后这一圈会顶到画面中部，太密就从"框住棋盘"变成"挡住棋盘"）。

## 联网多人：方案结论（用户问询，尚未开工）

**核心判断：这是回合制棋类，决策点每回合只有"掷骰"一次，所以完全不需要帧同步或状态机同步。
正确形态是「事件广播 + 各端本地重放」**——只传意图（谁、什么动作、点数），
各端用自己的 `director` 跑同一套动画脚本。

这个项目天然占便宜：`engine.ts` 是纯规则核心、已和渲染解耦，`director.ts` 是 await 式脚本序列，
所以同步量极小。**相机、粒子、音效、彩带、冲击环全是本地表现层，一律不入同步**——这是省掉 90% 同步量的关键。

改造面（按依赖顺序）：
1. `engine.ts`：不动。
2. `director.ts`：从"自己决定流程"改成"等指令 → 应用 → 播动画"；关键是加一个**回合安全点**（本地动画播完才允许推进下一步）。
3. `store.ts`：加 `roomId` / `seatIndex` / `netStatus`；`PlayerState` 已经有 pos，天然可序列化。
4. `Lobby.vue`：加"创建房间 / 输入房间码加入"，`PlayerSetup` 的槽位直接映射成 seat。
5. **骰子点数必须由一端产生后广播**，绝不能让各端各自 random（否则四端点数不同，整局崩）。
   注意 `pieces.ts` 里 `Dice.roll` 用了 `Math.random()` 生成 yaw 四元数——那只是表现层，可以保留；
   但任何影响**逻辑**的随机都必须走 `rng.ts` 并随事件一起广播。
6. 断线：状态可序列化，重连时补发一个 snapshot 即可；超时则 AI 托管接替。

后端两条路线（待用户定）：
- A. WorkBuddy 内置云服务（数据库 + 匿名/登录）：文档里 Database 模块只有 CRUD/条件查询/分页，
  **没有列 realtime 订阅**，所以走 **1~2s 轮询**。回合制完全够用，零额外运维。
- B. 腾讯云开发 CloudBase：用 NoSQL 的 `watch()` 做实时推送（社区标准做法，官方有
  WorkBuddy×CloudBase 的联机象棋教程可参照）。实时性好，但要自己开环境、写云函数。

部署：静态包用 `workbuddy_sites_deploy` 发布即可拿到公网地址，玩家打开网址 → 创建/加入房间。

### 一个反复绊脚的坑：沙箱把 localhost 也走了代理
- shell 里 `HTTP_PROXY=http://127.0.0.1:63987`，`curl http://127.0.0.1:4399/` 会被代理拦掉，
  报 `502 upstream connect failed: Connection refused` —— **看起来像服务没起来，其实服务好好的**。
- 两个解法：`curl --noproxy '*'`，或者干脆用 **Node 的 fetch 探针**（undici 默认不读代理环境变量）。
- 判断端口有没有起来不要靠 `curl localhost`，直接用 Node 探针打 `127.0.0.1:<port>`。
- 顺带：前台 `cmd &` 起的后台进程会在命令返回时被回收，长驻服务必须用 `run_in_background`。

### 又一个发现：Chromium 其实能出网（走代理就行）
之前判断"沙箱里 Chromium 无出口"，结论**不准确**。给它配上
`proxy: { server: "http://127.0.0.1:63987" }` + `--ignore-certificate-errors`，
就能直接打开线上地址（实测 200、标题正确、canvas 渲染、零控制台错误）。
所以以后测线上不必再造"本地代理转发 /.cloud"的脚手架，直接拿真域名测即可。

### 部署器的一条重要约束（记下来免得再踩）
